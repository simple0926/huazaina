# 花在哪 · 数据保护规则

从 v2.0.2 起，作为这个项目的硬规则：

1. **同包名版本更新，不删除原来的记账记录。**
   - SQLite 数据库随 App 更新保留。
   - `Db.onUpgrade` 只允许做加法迁移：`ALTER TABLE`、建新表、回填字段；**禁止 DROP 表、禁止 DELETE 用户记录**。
   - 启动时如果已有记录、但 `welcomed` 标记丢失，只补标记，不弹欢迎、不清空。

2. **只有用户明确操作才会删除。**
   - 设置 → 清空所有数据（二次确认）。
   - 删除单笔记录（二次确认）。
   - 没有自动清理、没有「更新后重置」路径。

3. **升级前建议备份。**
   - 设置 → 备份 JSON；导出到 `下载/花在哪/`。
   - 未来修改数据库结构时，先按旧 schema 导出/复制一份，再迁移。

4. **旧 WebView 版 → 原生版是一次迁移，不是同包更新。**
   - 两版包名不同，存储不同；原生版不能直接读取旧版的 localStorage。
   - 必须先旧版「备份 JSON」，再原生版「从备份恢复」。
   - v2.0.1 的欢迎页、空列表、设置都有恢复入口。

5. **本地安全备份。**
   - 每次保存、编辑、删除、导入、离开 App，写 `files/huazaina-autosave.json`。
   - 升级后数据库为空时，启动会弹出「发现本地安全备份」，可一键恢复。
   - 用户明确「清空所有数据」时，同时删除安全备份，避免把主动清空的数据又恢复回来。
   - 备份在 App 私有目录，随同包更新保留；卸载 App 会一起删除，所以仍要定期导出 JSON。

6. **验收。**
   - v2.0.0 → v2.0.1 → v2.0.2 覆盖安装，模拟器上 2 笔记录保留。
   - 删库演练：删除 SQLite 数据库、保留安全备份 → 重启提示恢复 → 2 笔记录完整回来。
   - 后续每个版本发版前，重复一次「有记录时覆盖安装 + 删库恢复」检查。
